# ISO 20022 pain.001.001.03 Field Reference (Customer Credit Transfer Initiation)

This describes the fields actually produced by this project's message generator
(`data/pain001_generator.py`), in the same order they appear in the message. It is not a full
reproduction of the ISO 20022 specification — only the subset of fields this project's
synthetic payments use.

## Document root

- **`Document`** — the outermost element, in the `urn:iso:std:iso:20022:tech:xsd:pain.001.001.03`
  namespace. Everything below lives under a single `CstmrCdtTrfInitn` (Customer Credit Transfer
  Initiation) child.

## Group Header (`GrpHdr`)

One per message, describing the message itself rather than any single payment:

- **`MsgId`** — a unique identifier for this message.
- **`CreDtTm`** — creation date-time of the message.
- **`NbOfTxs`** — number of individual transactions in the message (always `1` for this
  project's single-transaction messages).
- **`CtrlSum`** — control sum: the total of all transaction amounts in the message (equal to
  the single transaction's amount here).
- **`InitgPty/Nm`** — name of the party initiating the message.

## Payment Information (`PmtInf`)

One batch of payment instructions sharing a common debtor and execution date:

- **`PmtInfId`** — identifier for this payment information block.
- **`PmtMtd`** — payment method; always `TRF` (credit transfer) in this project.
- **`NbOfTxs`** / **`CtrlSum`** — same meaning as in `GrpHdr`, repeated at the payment-info
  level.
- **`ReqdExctnDt/Dt`** — the requested execution date.
- **`Dbtr/Nm`** — debtor (sender) name.
- **`DbtrAcct/Id/IBAN`** — debtor account, identified by IBAN.
- **`DbtrAgt/FinInstnId/BIC`** — debtor's bank, identified by BIC.
- **`ChrgBr`** — charge-bearer code; always `SLEV` (shared: each party bears its own agent's
  charges) in this project.
- **`CdtTrfTxInf`** — one or more individual credit-transfer transactions (this project's
  generator always builds exactly one).

## Credit Transfer Transaction Information (`CdtTrfTxInf`)

The individual transaction itself:

- **`PmtId/EndToEndId`** — an end-to-end identifier that travels with the payment through
  every intermediary, used to match acknowledgements and detect duplicates (see `POL-0003`).
- **`Amt/InstdAmt`** — the instructed amount, carrying a `Ccy` XML attribute for the currency
  code (e.g. `Ccy="EUR"`).
- **`CdtrAgt/FinInstnId/BIC`** — creditor's (beneficiary's) bank, identified by BIC.
- **`Cdtr/Nm`** — creditor (beneficiary) name. This is the field screened against
  `data/sanctions_mock/` per `POL-0004`.
- **`CdtrAcct/Id/IBAN`** — creditor account, identified by IBAN.
- **`RmtInf/Ustrd`** — unstructured remittance information (a free-text reference, e.g. an
  invoice number).

## `RmtInf` is optional — this matters

`RmtInf` is genuinely optional in the schema, and is always the last element within
`CdtTrfTxInf` when present. A message that omits it entirely is still well-formed, schema-valid
XML — it is not a malformed message. This is exactly what makes "missing remittance
information" a *business-policy* violation (`POL-0001`), not an XML-schema violation: the
message parses cleanly either way, and only this institution's own policy requires the field
to be populated.
